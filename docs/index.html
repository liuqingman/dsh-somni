Design

两个半身：醒的一半，睡的一半

人类的大脑不会在开会时重构记忆，也不会在睡觉时保持在线。Somni 按同样的分工来设计：在线时薄，离线时厚——醒着只做最省的事，把整合留到没有延迟压力的时刻。

醒时：上下文是最稀缺的资源

不把记忆全塞进提示，只在「可能要用」的那一刻才让相关条目浮现；身份与未竟之事例外，它们常驻，因为每次行动都要用。

睡时：整理比记录更重要

把一天的流水账蒸馏成分层结论，同时做两件在线做不到的事——用新证据覆盖旧结论，以及让长期用不到的东西自然淡出。

判断标准：会不会被用到

记忆不是对过去的留档，是对未来的投资。所以条目按「用过的次数」增值，按「久未被用」衰减，而不是按时间堆积。

不打扰、不外求

整合不占用在线响应时间；复用宿主已有的模型，不引入额外账号——它该是 agent 自带的能力，不是又一个要配的外部服务。

发生 → 记录→ 空闲 → 蒸馏→ 新任务 → 浮现→ 被用到 → 更强
Memory model

像人一样分层的记忆

全部落盘为带 YAML front-matter 的 Markdown：能读、能改、能 grep、能进版本库。

Episodic · 情景

发生过什么。按时间线沉淀，带衰减与冲突裁决。

Semantic · 语义

事实与概念。稳定、可复用，冲突时以新证据覆盖旧结论。

Prospective · 前瞻

还没做的事。不随时间遗忘，完成才清除。

Procedural · 程序

怎么做。把重复成功的路径固化成技能。

Identity · 身份

我是谁。常驻系统提示，跨会话不漂移。

Dream · 做梦

空闲时把当天日志蒸馏成上面几层，顺带做信噪维护。

Quick start

零配置接入 Cordis

# 装插件
npm i dsh-somni

# 或直接克隆仓库
git clone https://github.com/liuqingman/dsh-somni.git
cd dsh-somni && ./install.sh

# 数据目录里就是你的记忆
ls ~/.somni/memory   # knowledge/ skill/ episode/ ...
